## `<nds>`

Every module of the package.

```eskiu
import <nds>;
```

`<nds/bin>` bounds-checked reads, `<nds/lz>` LZ10, LZ11 and BLZ, `<nds/narc>`
NARC archives, `<nds/rom>` ROM headers, file systems and overlays,
`<nds/sdat>` sound archives and their synthesizer, `<nds/wav>` WAV files,
`<nds/image>` RGBA images and PNG, `<nds/graphics>` 2D graphics and cell
animations, `<nds/model>` 3D textures and models, `<nds/text>` Gen 4 and Gen 5
message files.


## `<nds/bin>`

Bounds-checked little-endian reads over a byte buffer, shared by
every format in the package. A read that would go past the end gives 0, so
a parser never touches memory outside the buffer it was handed.

```eskiu
NdsData d = NdsData{data: p, len: n};
uint32 magic = d.u32(0);
if (!d.has(off, 16)) return Err<X, string>("narc: truncated");
```

## `<nds/graphics>`

The DS's 2D graphics files (NitroSystem G2D) to RGBA images.

```eskiu
NdsPalette pal = nclr_read(nclr.data, nclr.len)?;     // RLCN
NdsTiles tiles = ncgr_read(ncgr.data, ncgr.len)?;     // RGCN
NdsScreen scr = nscr_read(nscr.data, nscr.len)?;      // RCSN
NdsImage img = nds_render_screen(&scr, &tiles, &pal, true);
img.write_png("bg.png")?;
```

- NCLR palettes: BGR555 colors, all the palettes of the file in a row.
- NCGR tiles: 4 or 8 bits per pixel, as 8x8 tiles or as a linear bitmap.
- NSCR screens: tile number, flips and palette per 8x8 cell.
- NCER cells: groups of OAM objects (sprites) placed around an origin,
  drawn with 1D or 2D tile mapping, or over a linear bitmap atlas as the
  multi-cell sprites of later games use. Affine objects are drawn
  without their rotation (NANR animations carry it).
- NANR (and NMAR) cell animations: sequences of frames, each a cell (or a
  multi-cell) shown for a number of 60 Hz ticks, with an optional
  translation or rotation and scale. NdsCells_draw_frame draws a frame.
- NMCR multi-cells: cells placed around an origin, each playing a
  sequence of a NANR.

Colors are converted as the extraction tools do: each 5-bit channel times
255 / 31, rounded down. Color index 0 of a palette is transparent where
the hardware treats it so (screens drawn with transparent0, cells).

### NDS_ANIM_INDEX, NDS_ANIM_SRT, NDS_ANIM_TRANSLATE

### NdsAnimFrame

```eskiu
struct NdsAnimFrame {
    int cell;
    int duration;
    int rotate;
    int scale_x;
    int scale_y;
    int x;
    int y;
}
```

One frame: cell (an NCER cell, or a multi-cell for an NMAR) shown for
duration ticks of 60 Hz. rotate is a turn in 65536 steps, scale_x and
scale_y are fixed point with 12 fraction bits (4096 is 1.0), x and y move
the cell's origin. Frames without a transform have rotate 0, scale 4096
and x, y 0.

### NdsAnimSeq

```eskiu
struct NdsAnimSeq {
    int kind;
    int cell_type;
    int loop;
    int first;
    int count;
}
```

A sequence: kind (NDS_ANIM_*), cell_type (1 cells, 2 multi-cells), loop
(1 stop at the end, 2 repeat, 3 forward then back once, 4 back and forth
forever; anything else stops) and its frames in NdsAnims.frames.

### NdsAnims

```eskiu

    int count;
    *NdsAnimSeq seqs;
    List<NdsAnimFrame> frames;
}
```

The sequences of an NANR or NMAR: sequence i is seqs[i], its frames frames[first ..
first + count). Free with free().

## `<nds/image>`

RGBA images and a PNG writer.

```eskiu
NdsImage img = NdsImage_new(64, 32);     // transparent black
img.set(3, 4, 255, 0, 0, 255);
img.write_png("out.png")?;
defer img.free();
```

The PNG writer stores its pixels in uncompressed DEFLATE blocks: the files
are larger than a compressing encoder's but any PNG reader opens them, and
the package needs nothing beyond the standard library.

## `<nds/lz>`

The DS BIOS compressions and the backward LZ of ARM9 overlays.

```eskiu
Bytes b = nds_lz_decompress(data, len)?;   // LZ10 (0x10) or LZ11 (0x11)
Bytes o = nds_blz_decompress(data, len)?;  // overlays, the ARM9 binary
```

Every read and every back reference is checked, so corrupt data is an
error. Output is limited to 64 MB.

### NDS_LZ_LIMIT

```eskiu
const int64 NDS_LZ_LIMIT = 64 << 20;
```

The largest output a decompressor makes, in bytes (64 MB); data that says more is an
error.

### nds_is_lz

```eskiu
bool nds_is_lz(*uint8 data, int64 len)
```

True when the data starts like LZ10 or LZ11 data.

### nds_lz_decompress

```eskiu
Result<Bytes, string> nds_lz_decompress(*uint8 d, int64 len)
```

Decompresses DS BIOS LZ10 (type byte 0x10) or LZ11 (0x11) data; Err for another type,
truncated data, a back reference before the start, or an output over NDS_LZ_LIMIT. The
Bytes are the caller's to free.

### nds_unpack

```eskiu
Result<Bytes, string> nds_unpack(*uint8 d, int64 len)
```

LZ data decompressed, anything else copied as it is.

### nds_blz_decompress

```eskiu
Result<Bytes, string> nds_blz_decompress(*uint8 d, int64 len)
```

The backward LZ of overlays and the ARM9 binary: a footer at the end gives
the compressed span and how much the data grows; it decodes from the end
toward the start. Compressed bytes are read from the input, so a stream
that would overwrite itself in place still decodes.


## `<nds/model>`

NitroSystem 3D files. Texture sets (NSBTX, or the TEX0 block of
an NSBMD) to RGBA images, and the geometry of NSBMD models.

```eskiu
NdsTexSet ts = nds_texset(data, len)?;            // BTX0 or BMD0
defer ts.free();
for (i in 0..ts.ntex) {
    NdsImage img = ts.image(i, ts.palette_for(i))?;
    img.write_png(...)?;
    img.free();
}
NdsModel m = nsbmd_read(data, len)?;              // the first model
defer m.free();
```

Textures: all seven DS formats are decoded. 1 A3I5 (32 colors, 3-bit
alpha), 2 4-color, 3 16-color, 4 256-color, 5 4x4 compressed (with its
four block modes), 6 A5I3 (8 colors, 5-bit alpha) and 7 direct color.
Colors are 5-bit channels times 255 / 31 rounded down; the 4x4 blends are
made on the 5-bit values, as the hardware does.

Models: the first model of an NSBMD, its materials (with the texture and
palette names each uses) and its triangles grouped by material, read from
the render commands and the pieces' GPU command lists: positions in all
the vertex formats, texture coordinates, normals and vertex colors. Like
the Tallgrass tools this is made for, the node matrices are not applied
(single-node models such as map blocks come out right; posed multi-node
models do not), and skinning, texture matrices and animations are not
read.

### nds_block

## `<nds/sdat>`

The DS sound archive (SDAT) and a synthesizer for its sequences.

```eskiu
Sdat s = Sdat_open("sound_data.sdat")?;
defer s.close();
Pcm16 pcm;
s.render(s.seq_find("SEQ_BGM_FIELD"), 30.0, &pcm)?;   // 30 s at 48 kHz
defer pcm.free();
pcm.write_wav("field.wav")?;
```

An SDAT holds sequences (SSEQ, bytecode for the sound driver), sequence
archives (SSAR, the sound effects: many sequences sharing one block of
bytecode, each with its own bank and volume), instrument banks (SBNK),
wave archives (SWAR, PCM8, PCM16 or IMA-ADPCM samples), streams (STRM,
long PCM or ADPCM waves in blocks) and the SYMB names of each. The
synthesizer is a port of the Tallgrass engine's (engine/src/sdat.rs),
which models the DS driver:

- The driver runs at about 192 Hz (64 * 2728 cycles of 33.51 MHz). Each
  frame adds the tempo to an accumulator and runs one sequence tick for
  every 240, then updates the envelope, volume, pitch and pan of each voice.
- Volumes are in tenths of a dB: master, sequence, track, expression,
  velocity and envelope are added (20 log10(x / 127)) and turned linear
  when mixing.
- ADSR envelopes use the driver's attack and fall rate tables.
- Pitch is in 1/64 semitone: note minus the instrument's root, pitch bend
  times its range / 2, and the modulation LFO.

Output is 48 kHz stereo. The arithmetic, the libm calls and the order of
the floating point operations are the Rust engine's, so the 16-bit output
is the same sample for sample. Up to 32 voices sound at once (the oldest is
stolen, released ones first). Two limits keep corrupt data from taking
forever, and do not touch real sequences: a sequence may open at most 256
tracks, and a tempo set from a variable is capped at 65535.

## `<nds/text>`

The message files of the Gen 4 and Gen 5 Pokémon games (the
msgdata NARC of Diamond, Pearl, Platinum, HeartGold and SoulSilver; the
a/0/0/2 and a/0/0/3 NARCs of Black, White and their sequels).

```eskiu
NdsCharmap map = nds_charmap_load("charmap.txt")?;   // Gen 4 only
defer map.free();
NdsText t = gen4_text_read(f.data, f.len, &map)?;
defer t.free();
for (i in 0..t.count) {
    string s = t.text(i, NDS_TEXT_CONTROLS);
    printf("%d %s\n", i, s);
    free((*void)s);
}
```

- Gen 4: a count and a seed, then an offset and a size per message, each
  XORed with a key from the seed and the message's number. A message is
  16-bit codes XORed with a key that starts from the message's number and
  steps by 0x493D. Codes are game characters, turned into Unicode by a
  character table the caller loads (NdsCharmap: the package ships none); a
  message that starts with 0xF100 packs them in 9 bits, 15 bits to a word.
- Gen 5: a header (block and entry counts, the first block's size, the
  block offsets) and blocks (usually one) of entries, each an offset from
  its block and a length.
  A message is decrypted from its end: the last code is the 0xFFFF that
  ends it, which gives the key, and the key turns right by 3 bits per code
  going back. Codes are Unicode characters; the 9-bit form packs them 16
  bits to a word.

Messages are kept as items: characters, line breaks, the two page codes
of Gen 4 (scroll and clear) and control codes with their arguments (text
variables, colors, sizes, waits), so a tool can rebuild the text or turn
the codes into its own markup. NdsText_text writes one message as UTF-8.

```eskiu
void NdsCharmap_free(NdsCharmap* self)
```

Frees the table and empties it.

### nds_charmap_read

```eskiu
Result<NdsCharmap, string> nds_charmap_read(*uint8 data, int64 len)
```

A character table in the pret projects' charmap.txt format: one line
"HHHH=c" per code (four hex digits, then one character in UTF-8), comment
lines starting with //, and the function codes after a line starting with
"// Function codes", which are not characters and are not read. Lines that
map a code to more than one character are skipped, as are codes from 0x0E00
up (the line break, the page codes and the controls are read by the parser).

### nds_charmap_load

```eskiu
Result<NdsCharmap, string> nds_charmap_load(string path)
```

Reads a character table file (as nds_charmap_read) from path; Err when the file cannot
be read or a line is malformed.

### gen4_text_read

```eskiu

```

A Gen 4 message file, its characters through `map` (null: every character

### gen5_text_read

```eskiu
Result<NdsText, string> gen5_text_read(*uint8 data, int64 len)
```

A Gen 5 message file. Not checked against a game's files: see the README.

### nds_text_read

```eskiu
Result<NdsText, string> nds_text_read(*uint8 data, int64 len, *NdsCharmap map)
```

Reads either generation. A Gen 5 file starts with a block count of 1 to
16, the size of its first block, a zero word and the block offsets, the
first right after them and starting with the same size; a Gen 4 file is
anything else, read through `map` as gen4_text_read does.

### NdsText_text

```eskiu
string NdsText_text(NdsText* self, int i, int mode)
```

Message i as UTF-8, NUL-terminated; free it with free(). Line breaks are
written \n, and Gen 4's scroll and clear codes \r and \f (a backslash and
a letter). In NDS_TEXT_CONTROLS mode a control code is written in braces,
its name and arguments ({STRVAR_1 1, 0, 0}, {COLOR 1}, or {CMD_XXXX ...}
for a command with no known name) and a code with no character as \xXXXX;
NDS_TEXT_PLAIN leaves both out.


## `<nds/wav>`

16-bit PCM buffers and WAV files.

```eskiu
Pcm16 pcm = ...;                  // from Sdat_render
pcm.write_wav("out.wav")?;
Bytes b = pcm.wav_bytes();        // the same file in memory
```

### Pcm16

```eskiu
struct Pcm16 {
    *int16 data;
    int64 frames;
    int channels;
    int rate;
}
```

Interleaved samples: frames * channels values, left first for stereo.

### Pcm16_free

```eskiu
void Pcm16_free(Pcm16* self)
```

Frees the samples and empties the buffer.

### wav_bytes

```eskiu
Bytes wav_bytes(*int16 data, int64 frames, int channels, int rate)
```

A RIFF WAVE file: the 44-byte header, then the samples little-endian.

### Pcm16_wav_bytes

```eskiu
Bytes Pcm16_wav_bytes(Pcm16* self)
```

The buffer as a WAV file in memory (wav_bytes); the caller frees it.

### Pcm16_write_wav

```eskiu
Result<int, string> Pcm16_write_wav(Pcm16* self, string path)
```

Writes the buffer to path as a WAV file; Err when the file cannot be written.
